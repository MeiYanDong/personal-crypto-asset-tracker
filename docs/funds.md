# 全部资金

`/funds` 在原站点内合并个人钱包和服务器钱包。原来的 `/`、`/wallets`、配对、手动资产组、访问口令和五分钟锁屏保持原行为。

## 统计口径

- 资产按链 ID、地址和代币合约去重。EVM 地址不区分大小写，Solana 区分大小写。币种名称不能作为去重键。
- 同一地址可同时来自个人清单与服务器。服务器登记的项目归属优先用于资金视图，原个人分组配置不变。服务器表示部署位置，不代表另一份资产。跨服务器迁移或备份不会新增余额。
- 使用最新成功观测；失败不清零。余额保留最小单位整数字符串，合计使用 BigInt，展示美元时才转换为浮点数。价格来自现有个人资产快照中相同链、相同合约的报价，不根据符号跨链套价。
- 已计价总额仅合计有报价的余额和个人 DeFi 净值。MM 与风险标记资产单列为参考估值；无报价展示数量，不按零价值处理。旧价格、旧余额及未覆盖范围独立提示。
- 保守估值沿用现有政策：符合原规则的稳定币与 SPY 全额，其余八折。既有 DeFi 净值及 LP 凭证排重逻辑继续使用。未扫描服务器 DeFi、未登记币种和未连通服务器不表示无资产。
- 这是资产快照，不是盈亏账本。转入、转出、新增扫描范围、价格变化都能改变金额。

## 最小运行结构

继续使用 React/Vite、现有 Express API 和私有 Vercel Blob。没有新数据库、队列、前端框架或运行时依赖。资金页按路由延迟加载，地址接口每页最多 50 行，主页面不下载数千行余额。

- 云端 `observer.py`：Python 标准库、只读 RPC，原生币及登记代币约每 15–20 分钟采集一次；个人资产及 DeFi 约每小时调用原刷新管线。每 5 分钟检查本地计划，未到期不调用网站或 Blob。执行期间由 OS 文件锁防重入。部分链失败保留上次成功快照。
- Mac `discover.py`：约每小时复用现有 AWS CLI、阿里云 SWAS CLI、SSH 配置读取实例和公开钱包清单。上传公开地址与覆盖信息。云端没有 AWS root 凭证或 SSH 私钥。本机离线不影响已登记余额采集，但新资源发现延后。
- 访问令牌经 HMAC 派生独立采集凭证，只能操作资金采集端点，不能修改个人钱包配置或读取网页口令。资金 API 仍受原访问口令保护，响应禁止公共缓存。
- 新服务器会出现在已接入云账户的实例清单；首次 SSH 入口或新云账户需一次接入。停止、失联或缺失清单均保留已知地址，并展示缺口。不会启动服务器或交易服务。

## 新项目 / 新钱包自动登记

网页新增的个人钱包在额度内纳入下一轮个人刷新；超额保存明确报错，已有配置不变。执行池新增钱包会从当前项目的 `senders-public.json`、`fleet-public.json` 等公开清单发现；超额项保留在来源公开清单中，报告待接入，下次发现会重试，不扩大预算、不作为零资产。

新项目推荐保存 `/var/lib/<项目>/funds-public.json`，由项目部署维护公开地址清单。这个文件不含密钥，且只列本人的账户或已确认控制的合约：

```json
{
  "version": 1,
  "project": "example-project",
  "chainId": 4663,
  "accounts": [
    { "address": "0x1111111111111111111111111111111111111111", "owned": true, "role": "owner", "kind": "wallet" }
  ],
  "assets": []
}
```

每个代币的 `assets` 条目包含 `chainId`、`address`、`symbol`、`decimals`；不确定估值可加 `valuation: "reference"`。执行池使用 `role: "sender"`，受控执行合约使用 `role: "custody", kind: "executor"`。合约必须确认归属，不登记协议池或竞争对手地址。新链没有只读适配器时提示待接入，不伪造成功。

只读扫描范围为 `/var/lib` 与 `/opt` 中限定深度的明确公开文件名；不读 `.env`、钱包文件、私钥、助记词、交易账本或签名交易。未知项目缺链 ID 时不猜链。新增公开清单无需改前端。

## 运行与回退

云端服务：`asset-funds-observer.service` / `.timer`；代码 `/opt/asset-funds-observer/observer.py`，专用用户 `asset-funds-observer`；配置 `/etc/asset-funds-observer/worker.env` 为 0600；状态 `/var/lib/asset-funds-observer` 为 0700。

部署目标为已有 Robinhood Radar 主机，先核对 hostname 与共存服务。此辅助服务不产生收益，采用 `Nice=15`、`CPUWeight=10`、`CPUQuota=20%`（单核的 20%）、`MemoryMax=96M`、`MemorySwapMax=0`、`TasksMax=16`；五分钟 timer 仅检查本地计划，完整采集到期才运行。以低优先级限制资源占用，保留既有服务的资源。共享机探测时约 166 MiB 可用内存，故选择短时 oneshot，不驻留新 Web 服务。采集后复核峰值内存、耗时与共存服务。

## 固定资源预算（2026-11-01）

配置唯一入口为 `shared/funds-limits.json`；云端同名副本与 `limits.py` 一并发布。额度不能由公开清单或钱包数量自动提高。当前 6,884 个服务器链上账户、35 种登记代币、20 台服务器及 59 个个人地址均在额度内。

| 资源 | 上限与行为 |
| --- | --- |
| 自动接入 | 8,000 个链上账户、40 个登记代币、40 台服务器、已适配的 8 条链；保留已登记账户，超额新增待接入 |
| 每轮余额工作量 | 40,000 项；同时约束账户 × 代币，避免只限制钱包数却被代币数量放大 |
| Solana | 最多 8 个服务器账户；单次返回最多 256 个 token accounts，链快照最多 256 种资产；每个账户预留 256 项预算，覆盖额外 SPL 资产的增长 |
| 云端采集 | 2 条链并发，每轮最多 400 次 RPC（失败与重试也计数），430 次总 HTTP，40 MiB 应用层收发正文；单响应及解压后均不超过 4 MiB |
| 重试与熔断 | 成功切换的节点在本轮优先复用；每条链最多 32 次单项补查，每项只做一次网络尝试；连续 3 个整批失败停止该链本轮采集，保留旧快照 |
| 运行时间 | 12 分钟应用预算，14 分钟 systemd 强制超时；CPU / 内存 / swap / 进程数使用上述硬限制 |
| 采集频率 | 每轮开始前持久化预约，服务器每天最多 96 轮（UTC），至少间隔 15 分钟；崩溃、中断、失败不返还次数，手动请求并入正常周期 |
| 个人资产 | 最多 75 个地址；自动与手动共用每天 24 次、间隔至少 15 分钟的预约；每轮最多 240 次外部请求、16 MiB 累计响应、2 MiB 单响应、240 秒网络请求预算；自动任务仍约每小时运行 |
| 跨实例防重 | 私有 Blob 原站读取 + ETag 条件写，先抢占预约再调用外部 API；竞争失败或预算存储不可用时不继续刷新；无新增数据库 |
| Mac 发现 | 整轮约 10 分钟期限，最多 3 个 SSH 并发、40 台接入机；AWS 最多 32 区域、每区一页 100 实例；Aliyun 最多 120 次 CLI 调用、每区一页，超额明确保留 PARTIAL |
| 单机公开清单 | 15 秒墙钟、4 秒 CPU 软限制 / 5 秒硬限制、128 MiB 虚拟内存，最多 128 文件 / 16 MiB 内容 / 10,000 地址；SSH / CLI 捕获输出限制 4 MiB |

服务器余额正常规模约 29,468 个实际观测项；预算中给动态 SPL 资产预留容量，当前占用 29,716 / 40,000 项。每天 RPC 的程序上界为 400 × 96 = 38,400 次；这包括重试，正常请求数应显著低于上界。应用层正文计数不包含 TLS/TCP/header 开销，也不是供应商账单。Vercel 函数、Blob 读写 / 流量及页面访问另行计量；固定数据规模、刷新频率和个人外部请求预算约束自动增长，不能据此宣称整账户零费用或设置了平台消费金额上限。

只覆盖最新快照与一个预算状态文件，不追加逐钱包历史。Mac 两个运行日志各保留约 1 MiB 当前文件和一个旧文件。余额失败或额度触顶沿用旧观测并提示缺口；待接入不是零余额。预算状态文件损坏时停下采集，不能自动清空状态重置额度。

页面「覆盖与更新说明」展示容量与最近一轮请求数、收发量、耗时、内存。提高额度前根据这些实测值复核；不要只增加账户数而不核对余额乘数、网络和共享主机余量。

后端 TypeScript 使用 NodeNext 检查，与 Vercel 的 ESM 运行规则一致；JSON 配置导入必须带 `with { type: "json" }`。生产发布先用 `vercel --prod --skip-domain`，通过 `vercel curl` 验证带口令接口后再 `vercel promote`；不能仅凭构建显示 READY 就认定服务已恢复。

Mac 配置为 `~/.config/personal-asset-tracker/discovery.json` 与 `worker.env`；launchd 标签为 `com.myandong.asset-funds-discovery`，只读复用现有入口。日志仅记录计数与错误类别，不记录凭证。

回退：停止本项目 timer；卸载本机上述 launchd 任务；将站点恢复升级前 Git 版本。新文件均以 `asset-tracker/funds-` 为前缀，既有钱包与分组配置无需回退。个人后台刷新只更新原资产快照，与手动刷新口径一致。

验证：`npm run build` 包含原回归检查和 `check:funds`，覆盖重复来源、精确整数、未知值、汇总一致性、保守估值和后台权限；另做真实桌面、手机、搜索、分页和地址展开验收。构建目标 ES2022，保留第三方许可证注释，继续使用原有体积预算。
